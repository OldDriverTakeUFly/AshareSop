# 每晚 NBA 解说式热点复盘短视频子系统(recap)设计 spec

- 日期:2026-09-18
- 状态:设计已获用户逐段确认(§1 架构+选片 / §2 剧本+录制单 / §3 后期+调度+视觉质检闸)
- 落地方式:分期(C 方案)——一期「选片+剧本+双TTS+字幕+数据卡原料包」,二期「ffmpeg 全自动合成」收敛终态

## 一、背景与定位

用户想做一档**每晚更新的 A 股当日热点复盘短视频**,风格对标 NBA 赛事解说:慢镜头回放涨停/炸板等戏剧性瞬间、双解说搭配、比分牌式叠层、数据弹出卡。「有一点点学习教育意义又有娱乐性质」。

**产品形态拍板记录(2026-09-18 用户确认)**:

| 决策点 | 拍板 |
|---|---|
| 成品形态 | 抖音/视频号竖屏短视频(9:16,60-90s) |
| 画面素材 | **手机 App 盘口回放功能录屏**(真实软件质感+最强回放感;接受录制环节人工) |
| 解说配音 | 双 TTS(实况解说+嘉宾分析两个音色) |
| 选片机制 | 全自动戏剧性评分→生成录制任务单,人工照单录,3-5 只/期 |
| 后期流水线 | 分期:一期原料包+剪映人工拼,二期 ffmpeg 全自动合成 |
| 发布 | **永远人工**(沿用全项目铁律) |

**每日人工成本边界**:照录制单录屏(约 8 分钟)+ 素材丢 inbox + (一期)剪映拼接 15-20 分钟;其余全自动。

## 二、子系统架构

新独立子系统 `davis_analyzer/recap/`(与 limitup/thermometer/intraday 同级),CLI:

```
python -m davis_analyzer.recap {select|script|sheet|audio|post|status}
```

数据流:

```
19:35 盘后数据齐(涨停池/龙虎榜/日线,全部复用既有采集链)
   ↓ ① select   戏剧性评分 → top3-5 候选+每票剧情点 → candidates.json
   ↓ ② script   LLM 生成双解说剧本(数字全锚 facts)→ episode.json + facts.json
   ↓ ③ sheet    录制任务单 → 飞书推送
━━━━━━ 人工:照单手机录屏(一票一文件)→ 丢 recap/inbox/{date}/ ━━━━━━
   ↓ ④ audio    双TTS分段配音+字幕SRT+数据卡PNG → episodes/{date}/原料包/
   ↓            (一期终态:剪映人工拼;数据卡先过视觉质检闸)
   ↓ ⑤ post     (二期)ffmpeg 自动合成+成片抽帧过视觉质检闸 → 预览 → 人工发布
```

目录约定:

```
davis_analyzer/recap/
  inbox/{date}/                  # 录屏素材投递(文件名协议见 §六)
  episodes/{date}/
    candidates.json  episode.json  facts.json
    原料包/  (audio/*.mp3, subtitle/*.srt, cards/*.png, 拼接说明.md, durations.json)
    final/   (二期成片)
```

台账:共享 SQLite(market_data.db)新增 `recap_episodes` 表,状态机 `selected → scripted → sheeted → recorded → packed → composed`(二期)→ `published`(人工标);每期文件即真相源,台账只记状态与指纹。

## 三、选片引擎(select)

**评分是「节目效果分」,不是投资分**——单一真相源 `recap/constants.py`(`RECAP_DRAMA_WEIGHTS`),与项目「权重单一真相源」惯例一致。

| 戏剧事件 | 数据来源 | 分数要点 |
|---|---|---|
| 炸板/回封 | 涨停池(炸板次数、首次封板时间) | 炸板次数越多越戏剧 |
| 地天板/天地板 | 涨跌幅+振幅(日线) | 极端反差最高分 |
| 连板天梯争夺 | limitup events 连板数 | 最高板=积分榜首 |
| 游资对决 | 龙虎榜席位 | 知名席位=球星对位 |
| 大长腿 | 振幅(日线) | 振幅>12% 起步 |

约束与降级:

- **编辑多样性**:同板块最多 2 只;单期至少 1 只「教育性」段落(板块/资金逻辑叙事,非纯爽点)。
- **v1 不依赖分钟线**(重要简化):涨停池自带首次封板时间/炸板次数,日线自带振幅/涨跌幅,足以定位剧情点;分钟线(尾盘偷袭检测等)留作以后加分项,不动 intraday 持仓宇宙。
- **冰点日降级**:当日无戏剧事件时自动降级「今日无战事」极简剧本(指数比分牌+一段嘉宾点评,也是一种节目效果)。
- 产出 `candidates.json`(含每票剧情点时间窗、事件标签、facts 摘要)。

## 四、剧本与解说(script)

**固定骨架**(总长 60-90s):开场比分牌 10s → 3-5 只票各 15-25s(常规 3-4 只,满 5 只时压缩至 15-20s/只)→ 片尾明日看点 10s。

**双解说人设**(TTS 两音色):

- 实况解说(激情型):喊动作、制造紧张感;
- 嘉宾分析(娓娓道来型):讲资金逻辑、板块叙事——「教育意义」的载体。

**NBA 转播语言映射表**(节目灵魂,固化于 `recap/style.py` 常量,LLM prompt 引用):

| A 股事实 | NBA 解说语言 |
|---|---|
| 涨停封板 | 扣筐得手;尾盘板=压哨绝杀 |
| 炸板 | 被帽/关键失误 |
| 连板天梯 | 积分榜/连胜纪录 |
| 游资席位 | 球星对位(席位名=球员名) |
| 三大指数+涨跌家数 | 片头比分牌 |
| 振幅/换手 | 数据弹出卡 |

## 五、facts 与合规纪律(沿用 cardgen 铁律)

- **数字纪律**:剧本任何数字(涨停时间/连板数/振幅/席位金额/指数点位)必须来自 facts 表,由 select 从数据库直取注入 prompt,**LLM 只组织语言不产生数字**。
- **validator 四道闸沿用**(数字全量核对/敏感词/完整性/事实自检),敏感词表在 cardgen 基础上新增视频专用词条(买入/抄底/上车/必涨等)。
- **定性为资讯复盘,不荐股**:解说只描述已发生事实;片尾固定免责字幕「内容仅为盘面复盘记录,不构成投资建议」。
- facts.json 格式沿用 cardgen 惯例(带来源锚点:涨停池查询/龙虎榜查询指纹)。

## 六、录制任务单与文件名协议(sheet)

**录制单**(markdown + 飞书推送,沿用运营群通知模式;群推送文案铁律:tags 若有必须最后一行):

```
## 2026-09-18 录制单(预计 8 分钟)
1️⃣ 600XXX 某某股份(3连板·地天板)
   App路径: 搜索代码 → 分时 → 盘口回放
   回放区间: 09:30-10:15 | 建议倍速: 1x
   ⚠️ 注意点: 09:47 附近跌停拉起动作是本段主角,务必完整录到
   保存为: 20260918_600XXX_1.mp4
2️⃣ ...
```

**文件名即协议**:`{YYYYMMDD}_{ts_code}_{序号}.mp4`——后期按文件名自动对位剧本段落,免去在录屏内搜索剪辑点。素材丢 `recap/inbox/{date}/`;audio 阶段 v1 手动触发,watch inbox 自动触发留作可选增强。

## 七、一期:原料包(audio)

检测 inbox 文件齐备后运行,产出 `episodes/{date}/原料包/`:

- **双 TTS 配音**:edge-tts(免费无 key,可替换接口封装,日后换付费音色不动架构);每段落单独 mp3 + `durations.json` 时长清单。
- **字幕**:SRT(剪映可直接导入),竖屏大字样式。
- **数据卡图片**:片头比分牌+每票数据卡,html→png 复用长图卡工具链(render_longpics.py 同源方法)。
- **拼接说明.md**:每段素材对应音轨/字幕/数据卡+建议顺序。
- **音画守恒校验**:每段解说时长 vs 素材时长(ffprobe),素材不足提示「回放放慢倍速重录或解说砍一句」。
- **视觉质检闸(一期范围)**:数据卡/比分牌 PNG 逐张过 `scripts/content_publisher/vision.py`(结构化 JSON 结论,主模型只消费结论;依据视觉任务规范 2026-08-29),检查文字可读/无溢出/无遮挡。

## 八、二期:自动合成(post)

- ffmpeg:素材变速对齐解说时长 → 顶部安全区叠比分牌/数据卡(overlay)→ 混音(解说+音效,BGM -14dB 垫底)→ 1080×1920 导出。
- **音效包纪律**(沿用配图纪律精神):只用 CC0/公有领域音效(欢呼/哨声/buzzer/鼓点转场),每条登记来源与 license。
- **视觉质检闸(二期范围)**:成片自动抽帧(片头 1+每票首/中/尾+片尾 1,≤12 帧控制 token 成本)过 vision.py,检查叠层遮挡/字幕错位溢出/数字可读性/花屏黑边/竖屏构图;fail 帧列出问题,重合成或人工兜底。此类质感质检允许仅依赖视觉模型(±20px 精度铁律属发布按钮点击类场景,不冲突)。

## 九、调度与运行

- 工作日 19:35 systemd timer(本机定时体系是 systemd timer 非 crontab)跑 `select+script+sheet`,19:45 飞书推录制单;与温度计 19:35 timer 错峰安排(实施时核对具体时刻)。
- audio 阶段依赖人工素材,手动触发或 watch inbox;二期 post 在 audio 之后串联。
- 发布永远人工;`published` 状态人工标记。

## 十、数据与依赖

- **数据源零新增**:涨停池/龙虎榜/日线全部走既有采集链与缓存;不读 intraday_research.db(v1 不依赖分钟线)。
- 新增 pip 依赖:`edge-tts`;`ffmpeg/ffprobe` 系统可用性在实施计划第一步验证。
- LLM:复用根目录 .env 的 `LLM_API_KEY/LLM_BASE_URL`;视觉模型走 vision.py 既有配置(`LLM_VISION_MODEL` 可覆盖)。

## 十一、测试计划(pytest)

- 数字核对:剧本全部数字 vs 数据库回查(facts 纪律机器闸)。
- 敏感词全表对解说词全量扫描(含视频专用词条)。
- 文件名协议解析校验;音画守恒校验逻辑测试。
- 假素材(静态帧生成的短视频)烟测原料包全链路;二期补 post 合成烟测与抽帧质检闸测试。

## 十二、异常处理(无人值守纪律)

- 龙虎榜未披露:等待 ≤40 分钟(沿用 daily-market-scan 惯例)。
- 单项数据缺失:跳过该分数项继续评分,记录异常。
- App 回放功能改版:录制单生成照常(路径描述基于当期验证),人工兜底,不阻断。
- 冰点日:降级剧本照常推送录制单(或纯比分牌版)。

## 十三、边界与非目标

- 不做盘中实时,只做盘后复盘(与温度计定位一致)。
- 不荐股、不预测,只复盘已发生事实;不做自动发布。
- v1 不用分钟线、不做横屏母版(竖屏单一形态)、不做自动上传。
- 行情软件界面录屏的版权风险自担(自媒体复盘类内容常见做法,保留软件水印即自然归源);若平台投诉再评估。

## 十四、实施顺序(供 writing-plans 展开)

1. 环境验证(ffmpeg/edge-tts)+ recap 骨架与台账表;
2. select 选片引擎+测试;

4. sheet 录制单+飞书推送;
5. audio 原料包(TTS/字幕/数据卡/守恒校验)+数据卡视觉质检闸+测试;
6. systemd timer 接入+AGENTS.md 模块划分段同步;
7. (二期)post 合成+音效包+成片抽帧质检闸+烟测。
