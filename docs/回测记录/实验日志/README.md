# 实验日志（Experiment Log）

> **定位**：策略每一次改动的完整决策链存档——思路从哪来、改了什么、结果如何、为什么采纳/否决。
> **原则**：负结果同样有价值（防止重复踩坑），所有结论必须可追溯到数据。

## 为什么有这个目录

2026-08-18 之前的实验散落在 `logs/*.json`、会话记录和几份收尾报告里，
"当时为什么想做这个实验"的思路链没有留存，事后只能看到结论看不到推理过程。
本目录按编号顺序记录每个实验的完整生命周期，作为以后的参照。

## 条目模板

每条实验一个文件：`NNNN_YYYY-MM-DD_实验名.md`，包含六节：

```markdown
# NNNN: 实验名（日期）

## 1. 思路来源
这个实验的想法是怎么找到的（归因数据/用户直觉/文献/失败实验的副产品）。

## 2. 假设
明确写出可证伪的假设和预期方向。

## 3. 实验设计
变体定义、对照组、回测窗口、universe、判定标准（事先定好，防止事后挑数字）。

## 4. 结果
数据表 + 年度分解。负结果照写。

## 5. 决策
采纳/否决/条件采纳 + 理由。参数改了哪些。

## 6. 遗留
未回答的问题、衍生的下一个实验想法。
```

## 判定纪律（从历史教训沉淀）

- **单一变量原则**：每个变体只改一个机制，组合验证单独跑（overseas overlay 单独 +4.8pp、组合 -24pp 的教训）
- **全期 + 分年双看**：总量提升但好年份倒退的改动要警惕（过拟合到病灶年份）
- **机制验证**：A/B 前先烟测确认机制真的触发（防止"改了没生效"的假阴性）
- **收益/MDD/真Sharpe 三口径**：真 Sharpe = 日收益年化（rf=0），Calmar = 收益/MDD，两者不可混称
- **TradeRecord 用属性访问** `t.ts_code`，不可下标（踩过两次）
- **长回测必须脱离会话运行**（2026-08-20 事故教训）：`run_in_background` 的进程随会话关闭被连带杀掉（0003 首跑死在 trial 4，前 3 个结果一并丢失）。用 `setsid nohup .venv/bin/python xxx.py > logs/xxx.log 2>&1 &`；同时结果 JSON 应逐 trial 落盘而非最后一次性写（待改）
- **双关固化标准（2026-08-19 起）**：新因子需 五年全期 A/B（总量）+ 随机窗口×票池截断测试台（`scripts/abx/random_window_harness.py`，稳健性）双关才可固化；对照基准用截断池 EW 而非上证指数
