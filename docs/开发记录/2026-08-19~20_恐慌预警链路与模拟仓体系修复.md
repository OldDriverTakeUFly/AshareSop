## 一、盘前报告时序（invest_sop cron 链）

**现象**：8/19 盘前 SOP 中午 11:03 才推飞书；8:00 的盘前操作策略表当天完全没推。

**根因（双因叠加）**：
- **A（慢性）**：08:15 `run_daily_advisor.py` 内嵌全市场因子打分（~2.4 万次 Tushare 调用，400/min 限速）。耗时演化：8/7 前 ~25min → 8/10 起 1h53m → 8/18 2h30m → 8/19 2h48m。膨胀主因即「二、退市股污染」（8/2 的 L+D+P 变更 7 天 TTL 后带入 339 只 D 股）+ watchlist 累积。
- **B（事故）**：8/9-8/18 期间 root crontab 重复安装过同批任务（journalctl 有 `(root) CMD` 铁证），`premarket_strategy.log` 被 root 创建 → 8/19 leo 用户的 8:00 任务在 shell 重定向阶段静默失败（无 MTA，错误被 cron 丢弃）。

**修复**：
- advisor cron `08:15 → 05:00`（数据全部依赖 T-1 收盘后内容，05:00 与 08:15 等价；~07:50 完成，赶在 8:00 策略表/8:30 morning_confirm 之前）。crontab.txt 已同步注释。
- 41 个 root 属主文件重建（重命名+重建法，免 sudo）；root crontab 用户已清理（journalctl 验证当日无项目相关 root 任务）。

**教训**：cron 任务"日志属主被污染 → 重定向失败 → 静默死亡"是本项目最阴险的故障模式，排查入口是 `journalctl -t CRON` + `ls -la logs/ | grep root`。

## 二、选股宇宙退市股污染（stock_universe / screen_top20）

**现象**：8/19 top20 榜单里紫天退(composite 99.4)居榜首、退海越/退园城占 #5/#6。

**根因**：`get_stock_list` 自 8/2（`26e4de1` 回测反幸存者偏差修复）起包含 L+D+P 三种状态——设计本身正确（docstring 明说下游自滤）；但 `build_stock_universe` 只按名称排除 `["ST","*ST"]`，从未按 `list_status` 过滤。**339 只 D 股每天进入实盘选股宇宙**。退市股暴跌残影被因子读成"困境反转+极低估值分位"→ 失真高分霸榜。

**修复**（`ae099c7`）：
- `build_stock_universe(active_only=True)` 默认：`list_status=="L"` + 名称含"退"兜底（整理期股仍为 L）。回测等需退市股场景显式传 `False`。
- 5 个调用方（pipeline/sector_pipeline/screen_top20/negative_factor_abx/refresh_report_data）全为实盘场景，一并修复；回测引擎不走此路径（自建宇宙），零影响。
- watchlist 清理 3 只退市股行；8-19 榜单热缓存 38 秒重生成（新榜首睿创微纳 70.31，20 只全部可交易）。
- 真实宇宙 5883 → 5544（去 D/P）→ 5338（去 ST）。

**连带发现**：`premarket_strategy._load_top20` 优先读 `top20_screen_latest.json`——该文件 7/12 后无任何写入方却一直存在，**盘前策略表的"新候选"整月引用 7/12 旧榜单**。改为优先最近 7 天日期文件（`803fadd`）。

## 三、模拟仓小资金算法漏洞（paper_trading）

**背景**：8/18 傍晚建 `mini_100k`（10 万，factor_threshold，config 为空 `{}`）接入 inject 后**恒 0 信号**。

**根因 1（结构性）**：inject 只传 `factor_scores={"_davis_scores": top20}`；FactorThresholdStrategy.evaluate 遍历的是 `snapshot.factor_scores`（五维）→ 空字典循环体不执行 → 恒 0 买入。executor 的自动因子计算仅在 `factor_scores is None` 时触发（executor.py ~2197）。**inject 链路对 factor_threshold 账号结构性失效**。
**处置**：mini_100k 切 `davis_double + {"top_n":5,"frequency":1,"min_score":60}`（与主仓 live_factor_test 同构，链路已验证）。

**根因 2（小资金边界，用户提示后审计发现两个真漏洞）**：
1. 10 万资金 top5 等权每槽 2 万：股价 ≥200 元一手买不起 → executor 静默跳过（`target_shares<100`）**且策略不顺位递补** → 系统性欠仓。
2. 科创板（688/689）限价单笔申报下限 **200 股**：旧代码统一 100 整手 → 会产生 100 股科创板买单，真实小账户不可执行。

**修复**：
- `account.min_buy_lots()`（`8788167`）：688/689→200，其余 100；`account.buy` 整手取整后强制下限、资金缩减路径同样校验。
- executor 跳过阈值、strategy 目标筛选接入（此两部分随 `bf1d975` 搭车入库，内容完好）。
- `DavisDoubleStrategy` 目标筛选新增可买性递补：`一手成本 ≤ 权益/top_n` 不满足则顺位递补下一名（`px×min_buy_lots > slot` 跳过）。
- 13 个单测（test_paper_board_lot.py）+ 一次性影子账号 E2E：mini 配置下睿创微纳（科创板一手 3.24 万>2 万槽）和兆易创新（~385 元）被正确跳过、递补宝丰能源/广合科技，5 槽满仓，账目分毫不差。

**排查须知**：`paper_trades.created_at` 存 **UTC**（=本地-8h）。看到"11:00:13"实为本地 19:00:13，别被误导成 advisor 干的。

## 四、尾盘实时价轮动（intraday_rotation，新模块，`94814a8`）

**动机**：原 inject 链路 19:00 盘后按当日收盘价成交——推送到达时价格已不存在，跟随只能次日开盘吃隔夜跳空，对实盘无借鉴意义。

**设计**（用户拍板：因子维持收盘价口径）：
- 14:40 用 **T-1 收盘因子**（top20_screen 日期文件）+ **实时行情**（东财→新浪双源，复用 intraday_manager 的 `_fetch_realtime_prices`）对主仓/小仓轮动；模拟按实时价成交，飞书推送留 ~20 分钟跟随窗口。
- 执行纪律与 executor 一致：板块整手/科创板 200 股/小资金递补/接近涨停(≥限幅-0.5%)拒买/接近跌停顺延卖出。
- **调度**：`intraday_manager` 主循环在 ≥14:40 的周期调用 `trigger_rotation()`（窗口守卫 14:40-15:00 + 最多 3 次重试，每 2 分钟一周期）；成功落 NAV 后 `has_run_on(T)=True`，19:00 inject 自动跳过——inject 降级为失败兜底。
- CLI：`python stockhot/invest_sop/scripts/intraday_rotation.py --dry-run|--force`（盘外 dry-run 自动回退昨收价）。

**为何不做实时因子（决策记录）**：三道坎——①数据源断层（daily_basic 盘后才发布，akshare 快照无 PE/PB/财务；四因子里只有动量和估值的价格分量盘中会动）②全市场重算 2.4 万次 API 装不进 20 分钟窗口 ③**回测口径断裂**（日频因子+收盘价执行是被验证的信号定义；盘中重算=交易从未回测过的策略+追脉冲风险）。后续可选渐进路径：小池子（top20-50）实时 overlay 重排 + 影子验证数周再决定是否接管。

**已知限制**：新浪降级源不含北交所 → 无价持仓卖出顺延/候选跳过（有日志，不出错账）；东财主源正常时覆盖北交所。

**明日观察点**：首个真实交易日运行——`stockhot/invest_sop/logs/intraday_manager.log` 找 `=== intraday_rotation` / `尾盘轮动` 关键字；收盘摘要应报"尾盘轮动：已完成"。

## 五、运维事故与教训（root 属主污染）

- **事故**：root crontab 8/9-8/18 存在重复任务 → 全仓 1495 个 root 属主文件（含 110 个 `__pycache__` 目录、sector_rv_cache 缓存、日期日志、回测记录 md）。
- **已修**：41 个可重建文件已改回 leo（重命名+重建，父目录属 leo 即可免 sudo）；`premarket_strategy.log` 用户自修。
- **待办**：`__pycache__` 目录需 sudo（仅影响导入性能，不影响正确性）：
  `sudo find /home/leo/Projects/CodeAgentDashboard -not -path "*/.git/*" -user root -exec chown leo:leo {} +`
- **ZCode 沙箱限制**：沙箱 no_new_privs 禁 setgid → `crontab` 命令在本环境永远 Permission denied（**spool 从未坏过，勿再误诊**）。沙箱内要改 cron：让用户在自己终端执行，或授权非沙箱模式。crontab.txt 与线上 crontab 目前一致（改 crontab.txt 后需跑 install.sh 或手工同步——见 session_state）。
