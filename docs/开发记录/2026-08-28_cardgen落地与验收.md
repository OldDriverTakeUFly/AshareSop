# cardgen 金融信息卡片生成系统——落地与验收记录

日期:2026-08-28 | 分支:cardgen(82d8ec2..c347f49,9 任务 + 终审修复波) | 设计 spec:docs/superpowers/specs/2026-08-28-cardgen-design.md

## 一、系统概貌

`davis_analyzer/cardgen/`(11 模块,CLI `python -m davis_analyzer.cardgen {init|ingest|validate|build|status|enqueue}`),补齐「研报/数据 → 卡片」的内容生产与质量段,与 scripts/card_factory(渲染)、scripts/content_publisher(发稿)松耦合对接:

- **双层内容模型**:结构化数字字段 `$fact` 强引用 + 叙事文本数值 token 全量提取比对,每个数字必须命中 facts.json 事实清单(带研报章节锚点或 Tushare 查询指纹)。
- **四道机器闸**(validate):数字全量核对 / 合规(敏感词全文本+尾卡免责+来源标注+waivers 豁免)/ 完整性 / 事实自检。不过不准 build;build 再查过期(expires_at);enqueue 打印发稿命令前再查一次。
- **台账**:storage/database/content_cards.db(cards/revisions/validate_log),版本 bump 须 reason,facts/spec digest 变更强制走修订链。
- **测试**:cardgen 86 项 + 全仓 1248 项全绿(渲染集成用例真实跑 node/playwright)。

## 四、agent 使用纪律(同步沉淀于 davis_analyzer/AGENTS.md)

①卡片任何数字必须登记 facts.json 且带来源锚点,叙事观点必须能指回研报章节;②已 rendered 版本变更须 `--bump --reason`,过期(expires_at)卡片禁止 build/enqueue;③不得修改 scripts/card_factory 与 scripts/content_publisher(对接只读)。
