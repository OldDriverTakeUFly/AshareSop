# 小红书金融卡片生产方法论——cardgen/publisher 全链路实战沉淀

日期:2026-08-29 | 来源:燧原科技篇(首发)、GPU四小龙篇(重建验收)、M10级材料篇三次全流程实战 + M3 自动发布对抗 | 适用:`davis_analyzer/cardgen` + `scripts/content_publisher`

> 一句话:**机器管数字对不对,agent 管观点有没有出处,人管值不值得发;不可逆动作(发布)在风控突破前留给人类。**

---

## 一、数字溯源铁律(最高优先级)

1. **每个数字必须有锚**:卡片上出现的任何数字,登记进 facts.json,锚点为「研报路径#章节 + 原文引句」或「Tushare 查询指纹」。引句保持**纯原文**——登记者的口径注释放 note 字段,不混进 quote(审计时 quote 必须能在源文件 grep 到)。
2. **四舍五入即失锚**:"+381.71%" 不能写成 "+382%",取整后的数字在源里不存在,溯源链就断了。卡片宽度不够就缩短周边文字,不改数字精度。
3. **闸门方向必须 fail-closed**:挡住比放过好。宁可为「9M」「FR-4」「2026-08」这类假阳性多改两轮文案,不可让无出处数字溜出去。实证:三次实战闸门共拦下 5 处真问题(52.3% 无出处数字、9M 裸数字×2、无出处的英伟达估值参照、尾卡缺来源),假阳性仅浪费约 10 分钟。
4. **豁免规则是暗坑清单,不是配置项**:日期(mm/dd、ISO、`2026-08` 半格式)、标识符(`688801`、`C600`、`FR-4` 字母-数字型)、中文数字、两位数区间(`20-25x` 与 mm/dd 同形)——每类都是实战踩出来的,新语料出现新误报就增补规则并配回归测试,规则只进不出。
5. **双向尾零自检**:value '17.360' 配 display '17.36亿'、value '2.40' 配 display '2.40亿' 都要放行——归一化匹配要双向。

## 二、内容设计预算(渲染层)

1. **stat 横排宽度预算**:三个大数字 stat 合计超宽 ~190px 即溢出(1080px 卡宽)。区间值("+381.71%~+473.46%")不适合做 stat,拆成下限单值或挪进正文。
2. **标题两行为限**:三行标题 + 完整组件必超 1440px 高。
3. **snap.cjs 溢出校验是免费的单测**:build 中止即布局回归,别绕过它删数据,要改文案。
4. **脚注日期用「2026年8月」不用「2026-08」**:后者会被数字闸拆出裸数;章节引用(§1.4-1.5)同理,改自然语言。
5. 叙事句里避免裸缩写数字("9M"→"前三季"),计数习语用中文数字("从零到一"不用"从0到1")。

## 三、平台自动化对抗(M3 对小红书)

按排查顺序沉淀,每层都有实证:

1. **登录态检测要看对 cookie**:创作者平台是 `galaxy_creator_session_id`,不是主站的 `web_session`——按错 cookie 名会永远等不到登录。
2. **上传入口无静态控件**:创作者首页上传卡走 File System Access API,必须 `expect_file_chooser` 拦截;找 `input[type=file]` 必超时。
3. **发布按钮在闭式 Shadow DOM**(`<xhs-publish-btn>`):DOM 文本扫描、get_by_role、伪元素全部不可达。可行路径是**几何/像素层**:
   - 首选 **PIL 颜色游程检测**:品牌红实心按钮 vs 红色文字(有间隙)天然可分,取最长连续游程的中心,布局漂移免疫、零依赖;
   - 次选 flash 视觉模型 bbox(±40px 精度,且会认错相似按钮,只配做兜底);
   - 末选宿主盒分数(布局会漂移,历史实证 0.72 与 0.93 两个值都"对过"——即都不可靠)。
4. **风控是分层的,别混为一谈**——并修正一个误判(2026-08-29 晚更新):「自动化检测静默吞发布点击」的早期结论**被证伪**——多轮点击无反应的真凶是**话题推荐浮层**:填完带 #标签 的正文后光标停在标签尾,编辑器弹出 hashtag 建议列表盖住发布按钮,吞掉点击并遮蔽红块检测。修法:填完后按两次 Escape 关浮层(已固化进 publisher.py)。**Escape 修复后,红块定位 → 点击 → 跳转成功页的全自动链路当日打通**。经验:归因"平台风控"前,先用截图+视觉模型确认 UI 状态——浮层遮挡、下拉、toast 都会伪装成"点击无效"。另:「频率限制」与「自动化检测」仍是两回事;**未验证的护栏数字(如每日2条)要如实标注为自律假设,不冒充平台规则**。
5. **人机接力是自动化未验证期的稳态**:脚本填好一切 → 人点发布 → 脚本监测 URL 跳转自动回写台账。全自动链路(红块定位+Escape 关浮层)已于 2026-08-29 验证通过,人机接力降级为兜底而非默认。

## 四、视觉任务分工

- **flash 视觉模型**(glm-5.3-flash):模糊判断类——卡片目检(排版/溢出/错别字)、失败截图诊断、内容一致性抽查。要求返回结构化 JSON,主模型只消费结论;
- **确定性检测**(PIL 像素/游程):精确动作类——按钮定位。规则:凡点击错对象会造成副作用(点到「暂存离开」会离开编辑器),不允许视觉模型单独决策;
- 原则:**精度要求高于 ±20px 的任务不外包给视觉模型**。

## 五、质量责任分层与时效

| 层 | 负责 | 载体 |
|---|---|---|
| 机器闸 | 数字对不对、词合不合规、要素全不全 | cardgen validate 四闸 + queue 敏感词扫描 |
| agent | 观点有没有出处、数字是否登记 | AGENTS.md 纪律三条 |
| 人 | 值不值得发、图好不好看、点发布 | review + 最终点击 |

时效:`expires_at = min(事实expires)`,build 与 enqueue 双重拒绝;估值/行情类事实短有效期(默认 as_of+7),叙事类可显式续期但必须写明依据。来源报告较旧(as_of 早于今天)时,**显式设置 expires**,否则整副卡被最旧事实拖过期。

## 六、发布节奏

- 单日上限、最小间隔是**自律护栏**而非平台规则(默认 2 篇/日、30 分钟间隔,常量在 publisher.py,可调);
- 排期黄金档 20:00-21:30;一天一篇是当前验证过的安全节奏;
- 发布失败留痕三件套:`publish_click.png`(点击前)、`publish_fail.png`(失败现场)、publish_log 台账行——事后可审计。

## 七、Checklist(新卡片速查)

- [ ] 事实全部登记,quote 为纯原文,可 `grep -c` 命中源文件
- [ ] 数字无自行取整(与源逐位一致)
- [ ] 脚注含「数据来源:」,尾卡含「不构成投资建议」
- [ ] 日期写法:ISO 或「X月」;禁「2026-08」「§1.4」
- [ ] validate 退出码 0;build 无溢出;RELEASE.expires_at 覆盖排期日
- [ ] flash 目检通过(布局/错别字;配图卡加查:裂图/重叠/图注可读)
- [ ] 配图(如有):src/license/credit 齐,license 无数字,布局模式按 §8.3 选,Commons 授权已 API 核实
- [ ] enqueue→review→schedule;排期在有效期与护栏内

## 八、配图规范(2026-08-30 沉淀:批量补图实战)

### 8.1 版权铁律(先于一切)

1. **人物肖像**:只用美国政府机构官方照片(联储/白宫作品=公有领域),Commons 可查;
2. **产品/实物/结构图**:只用 Wikimedia Commons 的 CC 授权图,授权与作者用 API 查询(`prop=imageinfo&iiprop=extmetadata`,取 `LicenseShortName`+`Artist`,**剥掉 HTML 标签取纯文本**),不要信文件页目测;
3. **查不到干净授权的图宁可不放**——账号商用,侵权一票否决;
4. 图片下载用 `Special:FilePath/<文件名>?width=900` 取缩略,落工程 `assets/` 目录,授权信息存 `assets/image_meta.json`。

### 8.2 spec 契约

```json
"image": {"src": "assets/xxx.jpg", "license": "CC BY-SA(署名-相同方式共享)",
          "credit": "描述,作者/Wikimedia Commons", "mode": "corner", "bottom": 240}
```
- `src/license/credit` 三必填,builder 缺一即拒(与 facts 溯源同级纪律);图注强制印在卡片上;
- **license 文本禁带数字**("CC BY-SA 4.0"→"CC BY-SA(署名-相同方式共享)",否则被数字闸拦);
- corner 模式 credit 要精简(长译名+全称会超 270px 宽被裁)。

### 8.3 布局模式选择(规则,不是试错)

| 模式 | 适用 | 参数 |
|------|------|------|
| 底部(默认) | 时间线卡 ≤5 个事项;summary ≤3 行 | `bottom: 150-240`,留白越大取越大 |
| `mode:"corner"` | 密集卡(7 事项时间线/多行结论/含引言框) | 右上角 270px 缩略,贴标签行右侧 |
| 不放 | 封面(stats+quote+tags 全占)、bars 卡 | 密度太高,硬放必压字 |

### 8.4 技术坑速查

- **图片绝不参与内容流**:`margin-top:auto` 方案必溢出(图注块固定开销 ~50px+,缩图百分比救不了),必须绝对定位;
- snap.cjs 溢出检测对绝对定位不生效(不占 scrollHeight)——**重叠只能靠 vision 目检抓**,配图卡的目检 prompt 必须含「照片正常显示(非裂图)/与文字无重叠/图注可读」三问;
- 补图 `--bump` 会强制旧文案过当前合规闸:旧工程配图前预期要顺带改写叙事(GPU/HVLP 实例:各 4 处旧违规被拦)。

### 8.5 留白修复与配图落位补充(2026-08-30 二次沉淀)

- **留白根因**:card.css 里 `.foot{margin-top:auto}` 会把卡片全部剩余空隙吸到脚注前,space-between 失效——builder 已注入覆盖规则(`.card{justify-content:space-between}` + `.card>.foot{margin-top:0}`),内容不足高的卡片自动均布,满卡零间隙不受影响,无需逐卡处理;
- **corner 模式的隐藏约束**:标题超长(如「+627.1%该看什么,不该看什么」)会与右上角图注碰撞——corner 卡的图注须精简到 20 字内;密集卡(timeline/bars/table 型内容卡)一律 corner,底部模式只用于确认有大留白的卡,否则必然压字(本轮 5 张全撞,规则再次验证)。

## 九、选品原则(2026-08-30 显性化:卡片选题从哪来)

> 背景:被问「卡片只覆盖写过的标的,是狭隘还是故意选热门?」——答案分两层,固化如下。

1. **卡片选题池 = 研报库的子集,这是刻意约束而非狭隘**:数字溯源铁律(§一)决定了没有研报锚点的标的无法过 validate 闸。不熟不发是合规优先的设计,也是与平台口胡账号的差异化立身之本。
2. **「热门」不是卡片层选出来的,是研究层传导的**:研报库按景气度方法论建,当前主线即 AI 算力,故卡片集中于热门标的。归因要归到上游选题,不在卡片层修。
3. **扩品的入口在研报层,不在卡片层**:先写短研报、再转卡片,锚的纪律不因扩品放松。现成路径:davis_analyzer 全 A 股四因子筛选(top20)产出的非热点低估标的 → 挑冷门名字补短研报 → cardgen 转化。
4. **冷启动吃主线流量,恢复后做差异化**:热门标的有真实搜索流量(搜「新易盛」的人远多于冷门股),冷启动阶段对;中期引入「冷门低估」系列吃长尾搜索、避开 AI 芯片内容红海,且低分位叙事时效窗口宽(expires 压力小)。
5. **账号风控观察期不动选品**:平台判定/限流期间只稳定输出已验证形态,不同时改两个变量(选品+节奏),否则无法归因。扩品决策等恢复正常发布一两周后,以后台搜索词进人与笔记来源分布的数据为准,不拍脑袋。

### 8.6 公告类内容品类边界(2026-09-01 合规闸裁定)

- **可做卡品类**:回购(已成交>进展>预案)/定增(读投向与时机)/收购重组(三问:标的是什么/作价倍数/支付结构)/业绩预告;
- **⛔否决品类**:增持/减持/询价转让——「增持」「减持」「卖出」本身在敏感词表,且内容本质是交易指向,平台风控大概率同口径识别。竞品账号做此品类是其合规风险,不是我们的机会空间;
- **新形态**:「公告+解读」= 数字对照(变更前后/额度与落地)+ 产业知识解读(周期位置/路线信号),对纯搬运号的降维差异;
- **数字闸单位规律(终版)**:fact 的 unit 必须等于文本数字后紧跟的单位字(亿/万/%),display 可带全称("2亿元"/"75万股");万米/亿美元/万元复合单位一律拆到最末单位字;
- tag_top 禁带生成日期(防旧日期暴露内容批量生成)。

### 8.7 全市场大事件雷达(2026-09-01 晚,管线内置)

- **形态**:日报新增雷达节——巨潮按 seDate 拉全市场当日公告(45 页×30 条,约 30 秒),品类过滤 + (公司×品类)去重 + 标题信号打分(重组/停牌/首次回购 > 定增预案/发行完成 > 注册稿 > 进展;负面排雷类与存量募集资金管理类跳过不列),输出 Top15;
- **定位:研报层扩品选题入口,不做卡**——接 §九.3 路径(大事件 → 补短研报 → cardgen 转化),不破坏数字溯源纪律;watchlist 重叠标的在雷达行标「已覆盖」;增减持类只计数不列明细(§8.6);
- **已知边界**:该接口不含北交所公告;金额多不在标题里,打分以事件类型信号为主;17:00 运行只能捕获当日 17:00 前披露——**晚间披露潮(19:00-23:00,回购/定增高峰)会漏**,需要晚间补跑一次才能兜全(`--no-radar` 可关,`--radar-top N` 可调)。
